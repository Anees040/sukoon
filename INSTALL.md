# INSTALL — getting this v0 codebase running

This zip is a **source overlay**, not a runnable build. It was written by an AI (Notion AI) **without a Flutter SDK or device**, so treat it as a solid v0 draft: expect `flutter analyze` to find issues that your local agent (Claude Code) must fix in the V-1 wave (see `docs/VERIFY_PLAN.md`).

## Step 1 — Create the host project (5 min)

You already created an empty Flutter project. The folder name does not matter, but the cleanest path is a fresh one:

```powershell
flutter create --org com.anees --project-name sukoon --platforms android sukoon_app
```

> If you keep your existing project instead, that is fine — just make sure `--project-name` equivalent (`name:` in pubspec) becomes `sukoon`, because all imports here are `package:sukoon/...`.

## Step 2 — Copy the overlay in

Copy **everything** from this zip into the project root, overwriting when asked:

- `pubspec.yaml`, `l10n.yaml`, `analysis_options.yaml`, `.gitignore`, `README.md`, `CLAUDE.md`
- `lib/`, `test/`, `assets/`, `docs/`
- `android/app/src/main/AndroidManifest.xml` (replace)
- `android/app/build.gradle.kts` (**merge, don't blind-replace** — see Step 3)
- `android/app/src/main/kotlin/com/anees/sukoon/*.kt` (add; delete the generated `MainActivity.kt` folder if it lives under a different package path)

## Step 3 — Gradle merge (important)

Flutter's Gradle template changes between versions. Open **your generated** `android/app/build.gradle.kts` and port these settings from ours into it (or use ours if the plugin blocks look identical):

1. `namespace = "com.anees.sukoon"` and `applicationId = "com.anees.sukoon"`  ← locks forever at first Play upload
2. `minSdk = 24`
3. The `signingConfigs` / `buildTypes` block (reads `key.properties`, falls back to debug signing so `flutter run` works before you create the keystore)
4. `isMinifyEnabled = true` + `isShrinkResources = true` on release

## Step 4 — First build

```powershell
flutter pub get
flutter gen-l10n
flutter analyze
flutter test
flutter run -d <your-tecno-device-id>
```

**Expected:** analyze/test may fail on first run — that is exactly what the `V-1` prompt in `docs/VERIFY_PLAN.md` is for. Paste `SUK-0` into Claude Code first, then `V-1`.

## Step 5 — Keystore (before first Play upload)

```powershell
keytool -genkey -v -keystore sukoon.jks -keyalg RSA -keysize 2048 -validity 10000 -alias sukoon
```

Create `key.properties` in `android/` (template in `docs/PLAY_RELEASE.md`). Both are gitignored — verify with `git check-ignore android/key.properties sukoon.jks`.

## What is intentionally NOT in this zip

- `android/gradle/wrapper/**`, `gradlew`, top-level `android/build.gradle.kts`, `android/settings.gradle.kts` — binary/template files that `flutter create` generates correctly for your Flutter version. Keep the generated ones.
- `lib/l10n/gen/**` — generated by `flutter gen-l10n`.
- Urdu Nastaliq font — optional bundle, see `assets/fonts/FONTS.md`.
- The Play listing screenshots and the signed keystore — manual (see `docs/PLAY_RELEASE.md`).
